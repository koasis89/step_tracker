# Flutter 비동기 처리 및 오류 핸들링 설명

이 문서는 현재 프로젝트의 코드에 적용된 Flutter의 비동기 처리(`Stream`)와 오류 핸들링(`onError`)이 어떻게 안정적인 데이터 흐름을 만들어내는지 설명합니다.

### 비동기 프로그래밍이란?

앱에서 시간이 걸리는 작업(예: 휴대폰 센서에서 데이터 가져오기, 인터넷 통신)을 기다리는 동안 앱 전체가 멈추면(UI가 '얼어붙으면') 안 됩니다. 비동기 프로그래밍은 이런 작업을 백그라운드에서 처리하고, 완료되었을 때만 알려달라고 약속하는 방식입니다. 이를 통해 앱은 항상 부드럽게 작동하고 사용자의 입력에 반응할 수 있습니다.

우리 앱에서는 **'걸음 수 센서 데이터 가져오기'**가 바로 이 비동기 작업에 해당합니다.

---

### 1. `Stream`: 끊임없이 들어오는 데이터의 흐름

`Future`가 '미래의 한 번'의 데이터를 약속한다면, `Stream`은 **'미래에 계속해서 들어올 데이터의 흐름'**을 약속합니다. 걸음 수는 계속해서 변하기 때문에 우리 앱은 `Stream`을 사용합니다.

`main.dart`의 `initPedometer` 함수가 이 작업을 수행합니다.

```dart
// lib/main.dart

void initPedometer() {
  if (_isSimulationMode) return;
  _stepCountSubscription = Pedometer.stepCountStream.listen(
    _onStepCount, 
    onError: _onStepCountError
  );
}
```

- **`Pedometer.stepCountStream`**: 걸음 수 데이터의 '수도꼭지'입니다. 플러그인이 센서로부터 데이터를 받을 때마다 이 스트림을 통해 데이터를 흘려보냅니다.
- **`.listen(...)`**: "이제부터 이 수도꼭지에서 물(데이터)이 나올 때마다 알려줘!"라고 구독(Subscription)을 신청하는 행위입니다. 이 코드는 실행 즉시 다음 코드로 넘어가며, 앱을 멈추게 하지 않습니다.
- **`_onStepCount`**: 데이터가 성공적으로 들어올 때마다 이 함수가 실행됩니다.
- **`onError: _onStepCountError`**: 데이터를 가져오는 도중 **오류가 발생하면** 이 함수가 실행됩니다. 이것이 바로 우리의 핵심 오류 핸들링 부분입니다.

---

### 2. 오류 핸들링: 안정적인 데이터 흐름의 핵심

`Stream`에서는 `listen`의 `onError` 콜백을 사용해 오류를 잡아냅니다. 우리 앱은 이 기능을 활용하여 매우 안정적인 사용자 경험을 제공합니다.

`_onStepCountError` 함수를 자세히 살펴보겠습니다.

```dart
// lib/main.dart

void _onStepCountError(error) {
  // 1. 개발자를 위해 오류 기록하기
  print('Pedometer Error: $error');

  // 2. 안전장치: 화면이 활성화된 상태인지 확인
  if (mounted && !_isSimulationMode) {

    // 3. 사용자에게 알리고, 앱이 계속 작동하도록 상태 변경
    setState(() {
      print("Sensor not found, switching to simulation mode");
      _toggleSimulationMode(true);
    });
  }
}
```

1.  **오류 기록 (`print`)**: 어떤 오류가 발생했는지 콘솔에 출력하여 개발자가 문제를 진단할 수 있게 합니다.
2.  **안전장치 (`if (mounted)`)**: 사용자가 화면을 벗어난 후에 뒤늦게 오류가 발생하여, 존재하지 않는 위젯의 상태를 변경하려는 2차 오류를 방지합니다.
3.  **안정적인 UX 보장**: 센서를 사용할 수 없을 때(예: 센서 고장, 권한 없음), 앱이 멈추는 대신 **`_toggleSimulationMode(true)`를 호출하여 자동으로 시뮬레이션 모드로 전환**합니다. 사용자는 앱을 중단 없이 계속 사용할 수 있습니다.

---

### 3. `dispose`: 자원 누수 방지 및 뒷정리

`Stream` 구독은 화면이 사라져도 자동으로 멈추지 않으므로, 직접 구독을 취소하여 메모리 누수를 방지해야 합니다. `dispose` 메소드는 위젯이 화면에서 완전히 사라질 때 호출되며, 여기서 뒷정리를 수행합니다.

```dart
// lib/main.dart

@override
void dispose() {
  _stepCountSubscription?.cancel(); // 수도꼭지 잠그기!
  _animationController.removeListener(_onAnimationUpdate);
  _animationController.dispose();
  super.dispose();
}
```

- **`_stepCountSubscription?.cancel()`**: `initPedometer`에서 생성했던 구독을 여기서 `cancel()`(취소)합니다. `?`는 구독 객체가 없을 때 오류가 발생하는 것을 막는 안전장치입니다.

### 요약

| 코드 | 역할 | 비유 |
| :--- | :--- | :--- |
| **`Pedometer.stepCountStream`** | 걸음 수 데이터의 지속적인 흐름 | 데이터 수도꼭지 |
| **`.listen(_onStepCount, ...)`** | 데이터가 들어올 때마다 실행할 작업을 예약 | "물 나오면 알려줘"라고 신청 |
| **`onError: _onStepCountError`** | 데이터 흐름에 문제가 생겼을 때 실행 | "수도관 터지면 알려줘"라고 신청 |
| **`_onStepCountError` 내부 로직** | 앱이 멈추지 않고, 시뮬레이션 모드로 전환 | 수도관이 터지면, 생수통으로 물을 계속 쓸 수 있게 함 |
| **`dispose()`의 `cancel()`** | 화면이 사라질 때 데이터 수신을 중단 | 집을 나갈 때 수도꼭지를 잠그는 것 |
