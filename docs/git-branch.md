# Git 브랜치 생성 및 가져오기

이 문서는 온라인 개발 환경(예: Firebase Studio)에서의 작업 내용을 로컬 PC 환경으로 안전하게 이동하고 개발을 계속하기 위한 Git 브라우저 사용법을 안내합니다.

## 왜 이 과정이 필요한가요?

온라인 개발 환경은 편리하지만, 때로는 인터넷 속도나 서비스의 성능 제약으로 인해 개발 속도가 느려질 수 있습니다. 이럴 때 현재까지의 모든 작업 내용을 Git 브랜치에 저장하여 원격 저장소에 올리면, 쾌적한 로컬 PC 환경에서 중단 없이 작업을 이어갈 수 있습니다.

---

## 1단계: 새 브랜치 생성 및 이동

현재 작업 내용을 별도로 관리하기 위해 새로운 브랜치(branch)를 생성하고 그 브랜치로 즉시 이동합니다.

- **명령어**: `git checkout -b <새_브랜치_이름>`
- **`<새_브랜치_이름>`**: 작업 내용을 잘 설명하는 이름 (예: `feature/login`, `fix/ui-bug`)

**실제 사용 예시:**
```bash
git checkout -b seperate_live_sim
```

이 명령어를 실행하면 `seperate_live_sim`이라는 브랜치가 새로 만들어지고, 현재 작업 공간이 해당 브랜치로 전환됩니다.

---

## 2단계: 변경된 모든 파일 스테이징 및 커밋

지금까지 수정하거나 추가한 모든 파일의 변경 내역을 하나의 작업 단위(commit)로 묶어 브랜치에 저장합니다.

### 2-1. 변경된 모든 파일 스테이징하기

`git add .` 명령어는 현재 디렉토리와 하위 디렉토리의 모든 변경사항(새 파일, 수정된 파일, 삭제된 파일)을 커밋할 준비가 된 상태, 즉 '스테이징(staging) 영역'으로 옮깁니다.

**실제 사용 예시:**
```bash
git add .
```

### 2-2. 스테이징된 파일 커밋하기

스테이징된 파일들을 하나의 의미 있는 작업 단위로 묶고, 어떤 작업을 했는지 설명하는 메시지와 함께 브랜치에 영구적으로 기록합니다.

- **명령어**: `git commit -m "커밋_메시지"`
- **`"커밋_메시지"`**: 변경된 내용을 요약하는 명확한 설명 (예: "feat: 로그인 기능 추가", "fix: 메인 화면 UI 버그 수정")

**실제 사용 예시:**
```bash
git commit -m "feat: seperate live and simulation mode using Provider"
```

---

## 3단계: 원격 저장소에 브랜치 푸시

로컬에만 존재하던 새 브랜치와 커밋 내역을 원격 저장소(예: GitHub)에 업로드합니다. 이 과정을 통해 다른 개발자나 다른 환경(내 로컬 PC)에서 이 작업 내역에 접근할 수 있게 됩니다.

- **명령어**: `git push <원격_저장소_이름> <브랜치_이름>`
- **`<원격_저장소_이름>`**: 보통 `origin`을 사용합니다.

**실제 사용 예시:**
```bash
git push origin seperate_live_sim
```

---

## 4단계: 로컬 PC에서 작업 내용 가져오기

이제 로컬 PC의 터미널에서 다음 명령어들을 순서대로 실행하여 원격 저장소에 업로드된 작업 내용을 가져옵니다.

### 4-1. 원격 저장소의 최신 정보 업데이트

원격 저장소에 새로 추가된 브랜치나 커밋 등의 최신 정보를 로컬 Git 저장소로 가져옵니다.

```bash
git fetch
```

### 4-2. 해당 브랜치로 이동

가져온 브랜치로 작업 공간을 전환합니다. 이제 PC의 VS Code나 다른 IDE에서 프로젝트를 열면 모든 코드가 동기화된 것을 확인할 수 있습니다.

```bash
git checkout seperate_live_sim
```
